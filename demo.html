Core Workflow

5 阶段门禁流程

Code Before Coding — 在编码之前先设计，每个阶段都有强制人工审查点

1
Phase 1

需求分析

通过系统化追问机制，消除需求中的模糊性，确保完整理解用户的真实诉求。不假设、不确定就问。

@requirement-analyst /analyze → 需求文档
🚧
Gate 1 — 需求文档人工审查
2
Phase 2

任务规划

将已批准的需求拆解为可执行的任务序列，定义每个任务的依赖、优先级和验收标准。

@planner → 实施计划
🚧
Gate 2 — 实施计划人工审查
3
Phase 3

架构设计

进行多方案技术对比，做出关键架构决策并记录 ADR，确保方案的合理性与可扩展性。

@architect → 架构方案 + ADR
🚧
Gate 3 — 架构方案人工审查
4
Phase 4

规格撰写

生成精确到接口、数据模型、边界情况的可实施级技术规格文档，作为代码实现的"法律"。

@spec-writer /spec → Spec 文档
🚧
Gate 4 — Spec 文档人工审查
5
Phase 5

代码实现

严格按照已批准的 Spec 进行编码实现，禁止自由发挥——遇到 Spec 缺失立即询问而非猜测。

@strict-coder /implement /review /sync → 可交付代码
Specialist Agents

10 个专业化 Agent

每个 Agent 只做一件事并做到极致，通过文档通信实现完全解耦

🔍
P1 requirement-analyst

需求分析专家

系统化追问，消除需求模糊性，5 大类追问清单确保理解完整

📋
P2 planner

任务规划专家

将需求拆解为可执行任务序列，定义依赖与优先级

🏗️
P3 architect

架构设计专家

多方案对比、技术选型、架构决策记录（ADR）

📝
P4 spec-writer

规格撰写专家

生成精确到接口的可实施级 Spec，覆盖边界情况

⚡
P5 strict-coder

严格实现专家

100% 按 Spec 实现，禁止自由发挥，Spec 即法律

🔎
code-reviewer

代码审查专家

多维度代码质量审查，涵盖可读性、性能、安全

🛡️
质量守护 security-reviewer

安全审查专家

认证、支付、权限等敏感场景自动触发安全审查，与 code-reviewer 并行执行

🧪
质量守护 tdd-guide

TDD 引导专家

引导测试驱动开发，RED→GREEN→REFACTOR 循环，Bug 修复时先写回归测试

📚
质量守护 librarian

文档同步专家

代码变更后自动同步更新相关文档，反向同步 Spec 与实现差异，防止系统熵增

🐛
bug-hunter

故障排查专家

系统化定位问题根因，提供修复方案与回归测试建议

Continuous Learning

持续学习系统

双模学习架构 — 主动学习快速建立认知，被动学习持续积累经验

📡

观察

通过 Hooks 自动记录开发者的每一次工具调用和操作模式

🔬

分析

Observer Agent 批量处理观察数据，识别重复出现的编码模式

💡

生成 Instinct

将高频模式转化为原子化的编码直觉（Instinct），初始置信度 0.5

📈

强化

每次验证成功后提升置信度，失败则降低，自然淘汰不适用的直觉

🧬

演化

高置信度 Instinct 聚类演化为可复用的 Skill、Command 或 Agent
